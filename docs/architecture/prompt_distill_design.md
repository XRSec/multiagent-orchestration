## 1. 宿主协议审阅与技术假设修正 (Host Protocol Alignment)

### 1.1 核心协议语义勘误
在 v1.0.0 早期设计中，曾假设通过 `UserPromptSubmit` 钩子返回 `hookSpecificOutput: { suppressOriginalPrompt: true, additionalContext: "..." }` 可以实现原地抹除/重写用户输入。经深层运行时机制审视，该假设存在根本性协议语义偏差：
1. **`suppressOriginalPrompt` 真实语义**：该配置是与阻塞决策（`decision: "block"` 或 Exit 2）强绑定的安全配置项，用于避免意外粘贴的凭据泄露至控制台。在常规执行放行（Exit 0）时，宿主直接忽略该属性。
2. **非阻塞模式下的组装机制**：宿主不支持就地变异（In-place Mutation）或抹除用户原始输入。钩子返回的 `hookSpecificOutput.additionalContext`，在宿主引擎内部作为附加上下文标记块（附加背景块）拼接到用户原始输入上方或下方一并交付主模型。
3. **无状态循环历史回放**：Claude Code 主智能体依赖底层转录本（Transcript，位于 `~/.claude/projects/.../{sessionId}.jsonl`）进行无状态循环回放。即便前端尝试改写单轮输入，宿主仍会在下一轮从磁盘全量回放前序全部日志与工具调用历史。

### 1.2 定位根本性重塑
插件定位从**“前端指令拦截与替换网关”**全面重构为**“高信噪比结构化背景增强引擎（High-SNR Context Augmentation Engine）”**。

## 2. 深度架构评估与核心议题实施规范

### 2.1 议题 1：多轮历史衰减与长序列认知漂移防御 (Context Decay Policy)
- **痛点**：一阶自回归马尔可夫链 $P_N = f(P_{N-1}, D_{N-1}, U_N)$ 在 $N \ge 8$ 轮后必然引发长序列认知漂移（Semantic Drift），高阶架构红线（如“保持向后兼容”）被逐步冲淡。
- **实施方案：分层记忆体系**：
  1. **全局长期锚点（Global Root Goal, $G_0$）**：
     - 在第 1 轮中由轻量模型提取并固化至 `meta.json`。
     - 全生命周期只读受控，严禁被自回归压缩二次提炼，全周期不可磨灭。
  2. **局部动态滑动窗口（Sliding Window Distillation）**：
     - 严格截断递归链条，仅维护深度 $K = 2$ 的局部执行窗口（$D_{N-1}, D_{N-2}$）。
     - 超出滑动窗口的早期产物从前置小模型输入中剔除，交由宿主底层转录本沉淀。
  3. **指数时间衰减模型（Exponential Time-Decay Model）**：
     $$A_i(N) = A_0 \cdot \exp(-\lambda (N - t_i))$$
     - $\lambda = 0.35$，初始评分 $A_0 \in [0.5, 1.0]$，阈值 $\tau = 0.2$。当 $A_i(N) < 0.2$ 时物理注销。
     - **工程红线豁免**：对于带有“始终”、“不要”、“严禁”、“必须”、“向后兼容”等断言的条目，强制设定 $\lambda = 0$，永不衰减。

### 2.2 议题 2：主模型 Prompt Cache 的实际影响与经济学推演
- **Anthropic 前缀缓存机制**：
  - 基于精准前缀匹配的 KV 缓存（Prompt Caching），要求 Token 0 起字节绝对一致，且前缀长度跨越 1,024 Tokens。
  - 宿主报文结构：
    $$\text{Request Layout} = [T_{\text{tools}}] \mathbin{\Vert} [S_{\text{system}}] \mathbin{\Vert} [H_{\text{history}}] \mathbin{\Vert} [U_{\text{current}}]$$
- **模式对比推演**：

| 评估指标 | 方案 A：强行篡改历史消息/指令重写 | 方案 B：保持历史稳定 + 尾端追加上下文 (本方案) |
| :--- | :--- | :--- |
| **缓存断点所处位置** | 处于首个被篡改历史消息的起始位置 | **稳定位于历史消息列表的最末端** |
| **前序上下文缓存状态** | 断点之后全部失效，强制触发 Cache Write | **$T_{\text{tools}} + S_{\text{system}} + H_{\text{history}}$ 享受完整 Cache Read** |
| **有效缓存命中率** | 趋近于 0%（历史被频繁重构） | **稳定在 88% 至 96% 之间** |
| **API 输入计费费率** | 频繁承受全额或 Cache Write（$1.25\times$） | **核心前缀仅需支付 Cache Read（$0.1\times$）** |
| **首字输出延迟 (TTFT)** | 显著劣化（主模型必须重算历史 Attention） | **维持极低延迟（直接加载预热 KV）** |
| **宿主契约兼容性** | 严重违背 Claude Code 现行 Hook 架构 | **原生兼容 hookSpecificOutput.additionalContext** |

### 2.3 议题 3：小模型意图提炼的“信息丢失与过度脑补”防御 (Hallucination Defense)
- **0ms 纯规则本地旁路引擎 (Deterministic Fast-Path)**：
  - **纯确认词**：`^(y|yes|ok|sure|continue|go\s*ahead|继续|好的|执行|推进|行|可以|好)$/i` $\to$ 静默放行（$<1\text{ms}$ 延迟，防脑补）。
  - **原生 CLI 命令**：`^(\/.*|git\s+.*|npm\s+.*|cargo\s+.*|pytest.*|pnpm\s+.*|bun\s+.*|yarn\s+.*|docker\s+.*)` $\to$ 透明透传。
  - **紧急阻断与回滚**：`^(no|stop|abort|cancel|revert|回滚|放弃|别动|停止|中断|撤销)$/i` $\to$ 直通放行，确保刹车最高优先级。
- **保真安全门禁 (Fidelity Guardrail Engine)**：
  - **输入输出约束规范**：剥夺小模型代码生成权限，严禁生成可执行代码块（` ```python ` 等），严禁虚构未出现过的路径，必须限制在四要素输出：`[全局根目标 G0]`、`[动作实体 Action]`、`[目标对象 Target]`、`[工程红线与约束 Constraints]`。
  - **确定性断言门禁**：
    1. 实体覆盖校验：扫描文件名（`\.[a-zA-Z0-9_]{1,10}`）、Git commit hash、CLI flags。若丢失超过 50%，判定失真。
    2. 膨胀率断言：当原始输入长度增长时，提炼输出长度不得超过原始输入的 3.5 倍（给予 350 字符的基础结构化空间）。
    3. 校验失败即刻触发 Fail-Open 原样放行。

### 2.4 议题 4：与 Claude Code 原生 /compact 及 PreCompact 钩子的全周期协同
- **消除状态裂脑（Split-Brain）**：
  ```
  [用户触发 /compact 或 宿主触发 Auto Compact]
                       │
                       ▼
            触发 PreCompact 钩子事件
       ┌───────────────────────────────────┐
       │ 1. 捕获通知，导出当前状态归档快照   │
       │ 2. 冻结写入流，释放文件互斥锁     │
       └─────────────────┬─────────────────┘
                         │
                         ▼
            宿主执行 Tier 4 深度蒸馏重构
                         │
                         ▼
      触发 SessionStart (matcher: "compact")
       ┌───────────────────────────────────┐
       │ 1. 物理重置 currentRound 为 1     │
       │ 2. 清空过期的局部滑动窗口         │
       │ 3. 重新锚定宿主 9 维度新摘要为基底 │
       └───────────────────────────────────┘
  ```

### 2.5 议题 5：并发与会话生命周期绑定安全
- **分片目录树拓扑**：
  ```
  ~/.claude/state/prompt-distill/
  └── ${session_id}/
      ├── meta.json                     (会话元数据与全局根目标 G0)
      ├── root.json                     (主会话状态与局部滑动窗口)
      ├── root.json.lock                (基于 PID 的互斥文件锁)
      ├── snapshots/                    (PreCompact 历史快照)
      └── subagents/
          ├── agent-a8f1b2.json         (子智能体专属分片)
          └── agent-a8f1b2.json.lock
  ```
- **基于 PID 的文件互斥锁与 Stale Lock 探活自愈**：
  - 使用 `O_CREAT | O_EXCL` 原子创建 `.lock`。
  - 集成 `process.kill(pid, 0)` 活性探针，5 秒超时且目标进程消亡时自动接管重置，杜绝崩溃死锁。
- **基于同卷原子替换的写入安全 (Atomic Inode Swap)**：
  - 同分区写入 `${filename}.tmp.${pid}.${Date.now()}` $\to$ `fs.fsyncSync(fd)` 刷盘 $\to$ `fs.renameSync` 原子覆盖。
- **机会主义垃圾回收 (Opportunistic GC)**：
  - `SessionStart` / `SessionEnd` 触发异步脱钩后台进程 (`spawn(..., { detached: true }).unref()`)。
  - 7 天 TTL 物理删除 + 100MB 存储上限下的 LRU 截断淘汰。

    ├── handler.mjs             # 生命周期总调度中枢 (Fail-Open / 事件分发)
