## 3. Per-impl notes (non-obvious only)

- **Protocol-level gap is systemic, not per-adapter.** S1 states plainly that ACP defines no inactivity timer, heartbeat, or deadline. Across S2, S3, S6, S7 no adapter adds one. All five verified implementations therefore derive liveness from either a `stopReason` arriving or the transport dying. The stale-running defect is a *host-side obligation* that no peer has discharged.
- **Instrumentation without thresholds.** claude-code-acp ships `SessionTiming.phase()` (S4) that logs `durationMs`/`totalMs` per phase. It is a logger; it defines no timeout and triggers no action. Useful as a near-miss: the data for a stall detector already exists there.
- **Ownership guards instead of timers (goose).** `ActiveRunDropGuard` (S7) couples run lifetime to the async task that drives it: drop ⇒ cancel token + `remove_agent_run`. This converts "owner died" into a deterministic terminal state without measuring silence. It is the only peer mechanism found that structurally prevents a stale running entry.
- **Resume is decoupled from turns.** claude-code-acp (`replayFrom.type === "start"`, `resumeSnapshot`, S3) and codex-acp (`resume_thread_from_rollout`, S6) can both reattach to a session after a crash, but neither reattaches to a *turn*: the aborted turn is simply absent from the next prompt. goose (S7) and our bridge behave the same way.
- **Gemini's retry is a passthrough, not a policy.** `GeminiEventType.Retry` carries `attempt`, `maxAttempts`, `delayMs` from the model stream; the adapter clears tool requests and emits a thought, but `handleRetryAttempt` defines no local cap or sleep (S2). The retry budget lives upstream in the model client.
- **codex-acp disables tool timeouts explicitly.** `tool_timeout_sec: None` for stdio and HTTP MCP (S6) — not an unset default, an intentional `None`. Any "hung tool call" is unbounded by construction.
- **Our bridge already classifies retryability but discards it.** `parseUpstreamErrorPayload` sets `retryable` from `QUOTA_EXHAUSTED` / `RESOURCE_EXHAUSTED|UNAVAILABLE|RATE_LIMIT|429|503` and `retryAfterMs`, and `buildTurnError` serializes it into `diagnostic` ([VERIFIED paseo-agy-acp/server/error-inspection.ts:158], [VERIFIED paseo-agy-acp/server/error-inspection.ts:311]). No consumer schedules a retry, so `retryAfterMs` is reported to the UI and dropped.

## 4. Recurring patterns, ranked by adoption

Denominator: 6 peer implementations examined (S1 protocol, gemini, claude-code-acp, codex-acp, goose, Qwen-inferred); Qwen counted only where the row is inherited-and-consistent.

1. **Turn ends only on `stopReason`; the protocol supplies no timeout — 6/6.** Every implementation returns a `stopReason` on the `session/prompt` response and none implements an inactivity deadline. [WEB S1, S2, S3, S6, S7; INFERRED for Qwen]
2. **No adapter-level retry of a dead turn — 6/6 (4 verified, 2 inherited/spec-silent).** Zero peers re-issue a prompt after a failed turn; failures surface as an error (`RequestError`, `Error::internal_error`, `StopReason::refusal`) and the client must re-prompt. [WEB S1, S2, S3, S6, S7]
3. **Cancel is a notification; the agent still answers the original request — 5/6.** `session/cancel` → mark unfinished tools cancelled, answer pending permissions `cancelled`, return `cancelled` as stop reason. Implemented in gemini (`cancelled` + abort), codex (`CancelNotification` → `thread.cancel()`), goose (`was_cancelled`), claude-code-acp (`session.cancel()`), spec. [WEB S1, S2, S3, S6, S7]
4. **Session resume decoupled from turn resume — 4/6.** claude-code-acp (`session/resume` + `replayFrom:"start"` + `resumeSnapshot`), codex-acp (`resume_thread_from_rollout`), goose (`load_session` + `provider.resume`), ours (`loadSession`/`resumeSession` on open). The in-flight turn is never reconstructed. [WEB S3, S6, S7; VERIFIED paseo-agy-acp/server/session.ts:207]
5. **Native/model retry is surfaced, not owned — 2/6.** gemini forwards `Retry` events with `attempt`/`maxAttempts`/`delayMs`; our bridge parses agy's retry warnings (`isRetryWarning`) and waits on `retryTimeoutMs` without initiating a retry. [WEB S2; VERIFIED paseo-agy-acp/server/brain.ts:371]
6. **Lifetime guard on the run owner (drop ⇒ cancel) — 1/6.** goose `ActiveRunDropGuard` only. [WEB S7]
7. **Per-tool timeout configured out-of-band (MCP `_meta.timeout` / explicit `None`) — 2/6.** goose reads `_meta.timeout` per extension; codex-acp sets `tool_timeout_sec: None`. Neither bounds a hung *turn*. [WEB S6, S7]
8. **Native stop reason is passed through verbatim — 3/6.** codex (`PromptResponse::new(stop_reason)`), claude-code-acp (`v2.PromptResponse`), goose (mapped enum). No peer normalizes beyond gemini/goose's small enum map. [WEB S3, S6, S7]

## 5. Transferability to paseo-agy-acp

State we do **not** track today (verified by reading `server/*.ts`), per mechanism:

1. **Turn watchdog (from pattern 1).** We track `state.turn`, `state.turnAbort`, `state.turnFinished` ([VERIFIED paseo-agy-acp/server/session.ts:529]) but no `turnStartedAt` / `lastActivityAt` and no timer. The `session/prompt` promise is awaited un-timed at [VERIFIED paseo-agy-acp/server/session.ts:2410]; only control RPCs get the 30 000 ms bound via `transport.request` ([VERIFIED paseo-agy-acp/server/transport.ts:65], applied at :336). Required new state: per-turn `lastProgressAt` (updated from `BrainTurnObservation.revision`, `brain-observer.ts:90`, and from every `sessionUpdate`), plus a deadline so a silent agent is converted into `finishTurnOnce(turnId,'failed', ...)`. Note the ordering defect this fixes: `stallTimeoutMs`/`retryTimeoutMs` are only consulted *inside* `settleBrainTurn` after the RPC returns ([VERIFIED paseo-agy-acp/server/session.ts:2472]), so a hung RPC bypasses stall detection entirely.
2. **Run-owner guard (from goose, pattern 6).** We have `turnAbort` and `resetTurnState()` in `finally`, but no registry keyed by `turnId` that fires on task drop. `onExit` mutates `state.failed` and terminalizes the *timeline* without itself calling `finishTurnOnce` ([VERIFIED paseo-agy-acp/server/session.ts:1249]); terminal turn state depends on the awaiting promise rejecting. Required new state: `activeTurns: Map<turnId, {abort, startedAt, lastActivityAt}>` with a drop guard, plus `finishTurnOnce` reachable from `onExit` directly.
3. **One-shot restart without resume target (from claude-code-acp `restartSession`, pattern 4).** `doRelaunch` throws when `loadSession` is unsupported ([VERIFIED paseo-agy-acp/server/session.ts:1393]) and every prompt after exit throws ([VERIFIED paseo-agy-acp/server/session.ts:2094]). Required new state: a `canStartFresh` flag derived from `agentCapabilities.loadSession` + `state.persisted`, and a replay cursor (we only persist `{sessionId}` at [VERIFIED paseo-agy-acp/server/session.ts:281]; `lastKnownStepIndex` and `userTurnCount` are recomputed on open, not persisted per turn).
4. **Consume `retryable` / `retryAfterMs` (from pattern 5 + our own classifier).** `buildTurnError` already emits `{quotaExhausted, retryable, resetAt, retryAfterMs}` in `diagnostic` ([VERIFIED paseo-agy-acp/server/error-inspection.ts:311]). Required new state: per-turn `attempt` counter and a scheduled retry keyed by `turnId` + `clientMessageId` (the idempotency key `state.prompts` already holds, [VERIFIED paseo-agy-acp/server/session.ts:536]), honoring `retryAfterMs` before re-dispatching `session/prompt`.
5. **Turn journal for crash resumption (from pattern 4).** `recordSessionClientMessage` persists `(ordinal, minStepIndex, clientMessageId)` ([VERIFIED paseo-agy-acp/server/session.ts:2183]) but nothing records that a turn was *in flight* at exit. Required new state: `{turnId, clientMessageId, nativeId, startedAt, status:'running'}` written before dispatch and cleared on `finishTurnOnce`, so a restart can mark the orphan `failed` instead of surfacing it as running.
6. **Tool-call timeout (from pattern 7).** No per-tool-call timer exists; `state.turnToolCallIds` is a bare `string[]` ([VERIFIED paseo-agy-acp/server/session.ts:513]). Required new state: `Map<toolCallId, {startedAt, kind}>` so a `tool_call` stuck in `running` can be failed independently of the turn.

## 6. Confidence and unknowns

Confidence: high for S1, S2, S3, S6, S7 on the two surveyed defects (each file was read directly; negatives are scoped to the file, not the whole repo). Medium for S7 (first 100k of 143k chars read). Low for S8 (Qwen: path existence verified, behavior inherited by inference).

Unknowns:
1. **claude-code-acp `stopReason` production** lives in `src/v2/session.ts` (not fetched); `cancel` semantics are visible in `src/v2/agent.ts`, mapping is not.
2. **opencode ACP turn handling** — `packages/opencode/src/acp/agent.ts` 404 under both `sst/opencode` and `anomalyco/opencode` (`default_branch: dev`); current path unresolved after 3 fetch failures.
3. **Crush, Copilot CLI, Amp, Cursor agent** — no source anchors established. Crush's recursive tree was truncated at 25% with no `acp` match in the visible slice (inconclusive, not evidence of absence). The other three were not probed within budget.
4. **Our own defaults** — `stallTimeoutMs` / `retryTimeoutMs` are optional `SessionOptions` ([VERIFIED paseo-agy-acp/server/session.ts:127]) and `provider.ts` constructs `SessionManager` without them ([VERIFIED paseo-agy-acp/server/provider.ts:68]); the effective defaults live in `brain.ts` / `brain-io.ts` (`RETRY_IDLE_TIMEOUT_MS`) and were not read, so no numeric value is asserted here.
5. **Zed's Rust client** — whether `agent-client-protocol`'s client side adds any deadline above the spec was not verified; S1 covers only the protocol contract.
